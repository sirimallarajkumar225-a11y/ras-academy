ECC Memory Errors: A Practical Guide

ECC (Error-Correcting Code) memory is designed to detect—and in supported configurations, correct—certain memory data errors. Error reporting, correction capability and response vary with the system architecture, memory configuration and firmware.

Corrected vs. uncorrected errors

A corrected event indicates the platform detected an error and successfully corrected it within its supported mechanisms. An uncorrected event means correction was not completed for that event. An uncorrected report needs careful assessment of severity, scope and system response; the label alone does not determine impact.

What evidence to collect

  • Timestamp and event source
  • Corrected or uncorrected classification and severity, where reported
  • Trend over time rather than a single count
  • Workload, environmental conditions and recent changes
  • Related system logs and platform event records

How to investigate safely

Start with read-only logs and supported management interfaces. Correlate evidence across sources, distinguish facts from hypotheses, and follow vendor-approved procedures. Never perform fault injection or hardware service on production systems.
